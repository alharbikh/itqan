# إتقان سمارت برو — إعداد استعادة كلمة المرور (#19)

## التصميم
- التوثيق والجلسات يداران بواسطة Cloudflare Worker عبر Cookies من نوع HttpOnly وSecure.
- المصادقة لدى Supabase Auth فقط، ولا تُحفظ كلمات المرور في قاعدة التطبيق.
- لا يستلم JavaScript في المتصفح رموز access_token أو refresh_token؛ يتحقق Worker من رمز الاستعادة ثم يغيّر كلمة المرور ويصدر Cookies.
- مدير **الموقع** وحده يملك إجراء إنشاء كلمة مرور مؤقتة. مدير المدرسة والموظف ممنوعان.
- لا تعيد هذه العمليات تغيير أي عضوية مدرسية أو صلاحيات وظيفية.

## إعداد البريد الإلكتروني (مطلوب قبل اختبار المرحلة 05)
1. افتح Supabase Dashboard لمشروع إتقان > Authentication > SMTP Settings، واربط خدمة SMTP خارجية موثوقة؛ لا تعتمد على مرسل Supabase الافتراضي للإنتاج.
2. افتح Authentication > Email Templates > Reset Password، وتأكد من وجود **رمز الاستعادة** داخل الرسالة:
   `رمز استعادة إتقان سمارت برو: {{ .Token }}`
   يمكن أيضًا إبقاء رابط الاستعادة القياسي، لكن واجهة إتقان الحالية تعمل بإدخال رمز البريد المكون من 6–8 أرقام، ولا تتعامل مع رموز جلسة URL hash في المتصفح.
3. أبقِ إعدادات Supabase Auth الخاصة بطلبات الاستعادة وكلمات المرور متوافقة مع حد التطبيق (8 أحرف على الأقل). لا تخفف سياسة Supabase الفعلية.
4. اختبر تسليم البريد على عنوان حقيقي مخوّل، وتحقق من معدلات إرسال الرسائل وتحديد محاولات الاستعادة.
5. يوصى بتفعيل إشعارات تغيير كلمة المرور والتحقق من إعدادات إبطال الجلسات عند أي حادثة أمنية.

## إعداد مفتاح الإدارة الخادمي (مطلوب قبل اختبار المرحلة 02)
- أضف إلى **Secrets** الخاصة بـ Cloudflare Worker العامل `itqan` السر `SUPABASE_SERVICE_ROLE_KEY` بالقيمة القديمة من نوع JWT service_role الموجودة في إعدادات API لمشروع Supabase، ولا تضعه أبدًا في `wrangler.jsonc` أو ملفات GitHub أو المتصفح.
- يُستخدم المفتاح في مسارات Worker المخولة فقط، بعد التحقق من جلسة المستخدم ومن دوره `site_admin`.
- إجراء الإدارة يستخدم `auth/v1/admin/users/:id`، ويوثق محاولة إعادة التعيين في `site_admin_audit` قبل تغيير كلمة المرور.
- إذا لم يكن السر مضبوطًا تُرفض العملية الخادمية وتظهر رسالة مناسبة دون كشف أي بيانات سرية.
- بعد الإعداد راجع صلاحيات الأسرار، وآليات التدوير، وسجل التدقيق.
- **لا تفعّل الاستخدام الفعلي قبل اختبار الصلاحيات والتغييرات الخادمية.**

## الشاشات
- `/login.html`: رابط «نسيت كلمة المرور؟».
- `/recover.html`: طلب رمز البريد + إدخال الرمز وكلمة المرور الجديدة.
- `/password.html`: تغيير كلمة المرور للمستخدم المسجل؛ وعند كلمة مرور مؤقتة يفرض التغيير قبل الدخول لبقية التطبيق.
- `/admin.html` > المستخدمون > «إعادة ضبط الدخول»: اختيار إرسال رمز استعادة إلى البريد المسجل أو توليد كلمة مرور مؤقتة وعرضها مرة واحدة فقط، مع سبب إلزامي لكلا المسارين.
- يتطلب تغيير كلمة المرور المؤقتة **إدخالها والتحقق منها مجددًا**، لا مجرد وجود جلسة سابقة.

## حدود معلومة
- صلاحية كلمة المرور المؤقتة محددة بـ 24 ساعة للتحقق من استخدامها. عند انتهاء المدة يلزم إنشاء كلمة أخرى إداريًا.
- كلمة المرور المؤقتة ليست رابطًا لإعادة الدخول أو وسيلة بديلة لتوثيق الهوية: يجب على مدير الموقع التحقق من هوية المستخدم خارج النظام قبل تسليمها عبر قناة آمنة.
- السجل يوثق **محاولة** إعادة الضبط قبل إجرائها. قد يتطلب التأكيد اللاحق مراجعة حدث تغيير الحساب في Supabase.
- عند تغيير كلمات المرور، يلزم مراجعة/إبطال الجلسات القديمة وفق سياسة الأمان المطلوبة؛ لا تفترض أن تحديث كلمة المرور يلغي جميع JWT السابقة تلقائيًا.
- لا تحوّل هذا المستند إلى إذن للنشر على الإنتاج: استكمل اختبارات الكود والتحقق ثم اطلب الموافقة على النشر وفق AGENTS.md.

## الاختبارات
- `node --test tests/password-recovery.test.mjs` للاختبارات المستهدفة.
- `node --check src/worker.js && node --check public/app.js && node --check public/admin.js` للتحقق من تركيب JavaScript.
- اختبارات قبول الكمبيوتر والجوال منفصلة ولا تدخل في شرط إكمال الكود.

## قاعدة البيانات
- أُضيف ترحيل `20261110141647_allow_audited_password_recovery_actions.sql` إلى Supabase ومصدر GitHub، للسماح بعمليتي `user.password.temporary_attempt` و`user.password.recovery_email` ضمن قيد سجل التدقيق.
- تم التحقق من القيد في قاعدة Supabase بعد تطبيق الترحيل.

## حالة التفعيل
- رُصد نشر تلقائي لـ Cloudflare Worker عقب تحديث `main`، فلا يُفترض أن تغييرات GitHub غير منشورة.
- إعدادات Worker الحالية لا تتضمن `SUPABASE_SERVICE_ROLE_KEY`؛ لذا يبقى مسار الإدارة معطلًا حتى ضبط السر.
- نتيجة اختبارات Node CI وتشغيل البريد الحقيقي غير مؤكدة، ولا يجوز اعتماد المهمة مكتملة بناءً على فحص تركيب JavaScript وحده.
