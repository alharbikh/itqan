# خارطة طريق إتقان سمارت برو — نسخة استعادة تقنية للمراجعة

**الحالة (تحديث 11 نوفمبر 2026):** خارطة متابعة معاد بناؤها ومُحدّثة وفق GitHub وSupabase وCloudflare. **لا تُعد تقرير مطابقة عناصر GitHub Projects**؛ لم يوفر الاتصال الحالي إجراءً لقراءة عناصر اللوحة، ويجب إبقاء ذلك مانع تحقق منفصلًا.

## الحوكمة
- المنصة: **إتقان سمارت برو (ITQAN SMART PRO)**؛ الفصل الكامل عن حضوري سمارت برو ونطاقه وخدماته.
- الواجهات والخادم: Cloudflare Workers. الحسابات والصلاحيات والبيانات والمرفقات: Supabase Auth/PostgreSQL/Storage، وRLS وجلسات HttpOnly.
- المدرسة هي النطاق الأساسي؛ إدارة التعليم بيانات وصفية اختيارية؛ الارتباط المدرسي النشط لا يتجاوز مدرسة واحدة.
- مدير الموقع وحده مسؤول عن إطار المعايير والأوزان، ومدير المدرسة عن ملفات منسوبي مدرسته وفق الصلاحيات، والموظف عن الشواهد وطلب الربط.
- لا بيانات افتراضية أو حقيقية حساسة في GitHub؛ لا إعادة تهيئة مدمرة لإنتاج Supabase؛ كل تحديث للمخطط بترحيل جديد واختبار معزول.
- **اختبارات القبول الحقيقية والبصرية مؤجلة حتى إكمال البرمجة واختباراتها الآلية؛ لا تُسجل ناجحة دون اختبار المالك.**

## نتائج مراجعة 11 نوفمبر 2026

1. **PR #22:** استبدال تأكيدات المتصفح الأصلية بنوافذ داخل الصفحة؛ نجح CI ودُمج.
2. **PR #23:** معالجة تضارب CSS مع سياسة CSP، القائمة الجانبية في إدارة المعايير، فحوص أمان الواجهات والاسترداد؛ نجح CI ودُمج.
3. **PR #25:** تفعيل روابط خدمات المدرسة المنفذة بالفعل، ومراجعة النصوص، واختبار تقليص منح TRUNCATE/TRIGGER/REFERENCES للدورين `authenticated`/`anon` على قاعدة **معزولة فقط**؛ نجح `app-and-security` و`schema-bootstrap` ودُمج.
4. قاعدة Supabase الإنتاجية: 50 جدولًا في `public`، و39 ترحيلًا مسجلًا. اختلفت أرقام ثمانية ترحيلات عن ملفات GitHub، لكن **نص SQL الأصلي متطابق حرفيًا (Git blob SHA-1: 8/8)**؛ يظل إصلاح التاريخ مطلوبًا قبل أي `db push`.
5. تقرير Supabase Security Advisor كشف منح TRUNCATE إلى `authenticated` على 21 جدولًا، و43 دالة SECURITY DEFINER تحتاج تدقيق صلاحياتها الداخلي، وتحذير إعداد كشف كلمات المرور المسرّبة. وجود `auth.uid()` في نص جميع الدوال فحص أولي لا يكفي لإثبات سلامتها.
6. لم ينفذ اختبار حقيقي جديد على الكمبيوتر أو الجوال؛ ولم تُبدل بيانات إنتاج Supabase أو DNS ضمن هذه المراجعة.

## الأعمال والأحكام المفتوحة

- [#24 — تقليص منح قاعدة البيانات](https://github.com/alharbikh/itqan/issues/24): تحويل SQL المختبر في البيئة المؤقتة إلى ترحيل رسمي جديد بعد مراجعة أثره، ثم تطبيقه على الإنتاج بتفويض محدد.
- [#26 — تسوية سجل الترحيلات](https://github.com/alharbikh/itqan/issues/26): 8 أرقام إصدارات متباينة مع تطابق تام لمحتوى ملفاتها، فلا يجوز إعادة تنفيذ SQL التاريخي أو تنفيذ `db push` دون إصلاح تاريخ الترحيل.
- [#27 — القرارات الإدارية غير المحسومة](https://github.com/alharbikh/itqan/issues/27): احتساب الدرجات الرسمي، تصحيح التقييم بعد الإغلاق، سياسة الاحتفاظ، وحدود تخصيص المواعيد ونقل الشواهد.
- المهام #10–#11 و#13–#17 و#19 تبقى مفتوحة للقبول الذي لم يُجر بعد؛ #20–#21 لا يبدأان قبل إنهاء البرمجة والقرار الإداري المتعلق بالأمان.

## معيار التصريح باكتمال البرمجة

لا يُستخدم وصف **«اكتملت كل مهام البرمجة»** إلا عند: (1) انعدام الفجوات البرمجية المعتمدة للمرحلة الحالية، (2) نجاح اختبارات JS وAPI وRLS وSQL على أحدث التزام، (3) معالجة #24 و#26 أو توثيق خطة/قرار صريح يقبل التأجيل ويمنع الترحيل غير الآمن، (4) مواءمة قائمة GitHub Projects الفعلية مع هذه الخارطة، (5) فصل القبول التشغيلي والبصري تمامًا عن ذلك.

**المصدر الوظيفي:** مسودة `itqan_functional_requirements_v0_1.md` المؤرخة 9 نوفمبر 2026، المرجع التحليلي السابق لا وثيقة اعتماد نهائي.

## تحديث معتمد — فصل صلاحيات مدير الموقع ومدير المدرسة (11 نوفمبر 2026)

- **قرار المالك:** صلاحيات مستقلة، مع السماح لحساب واحد بحمل دور `site_admin` ودور `school_principal` عند وجود عضوية `school_memberships` نشطة في مدرسة محددة، دون توريث تلقائي للأذونات.
- **المصدر الحاكم:** `docs/ITQAN_GOVERNANCE.md` وتحديث `AGENTS.md`، وعمل المتابعة [#37](https://github.com/alharbikh/itqan/issues/37).
- **حزمة P1/P2/P3:** ترحيل جديد يفصل `role_permissions` ويغير `itqan_private.has_school_permission` من مزيج صلاحيات النظام والمدرسة إلى التحقق من عضوية المدرسة فقط. تحقق خادم Cloudflare ولوحة المدرسة من الصلاحيات المستقلة.
- **المصفوفة الاختبارية:** مدير موقع فقط، مدير مدرسة فقط، موظف، حساب بدورين في مدرسة أ، مدرسة ب، إلغاء العضوية، إيقاف المدرسة، تعطيل الحساب. يجب أن تبقى خدمة `self.manage_portfolio` ومشاركة الشواهد متاحة فقط ضمن العضوية المدرسية، دون اكتسابها من دور مدير الموقع. تبقى وظائف إدارة المدارس والمستخدمين ونشر المعايير لمدير الموقع.
- **بوابة الإطلاق:** لا إنتاج قبل اجتياز `app-and-security` و`schema-bootstrap` على آخر التزام، ومراجعة خطة أثر تغيير صلاحيات المستخدمين، وتفويض تطبيق منفصل. اختبارات قبول الكمبيوتر والجوال مؤجلة؛ لا تُغلق لمجرد نجاح CI.
- **الحالة:** مطلوب تحقق آلي وتوثيق أثر الترحيل؛ لا يُوصف بالإنتاج المكتمل حتى تطبيق رسمي منفصل مع إثبات تحقق.

### الجوانب المتبقية بحسب الصلاحية والأثر

- **أعمال قابلة للتنفيذ آليًا:** مراقبة اختلاف الملفات العامة دوريًا، تسجيل Git commit SHA في وصف/وسم إصدار Wrangler عند **عمليات نشر معتمدة لاحقًا**، وتحديث خط اختبارات CI كلما اتسع النظام. أدوات النشر لا تُستخدم لإطلاق إصدار حالي دون موافقة.
- **مهام برمجية مفتوحة حتى اعتماد التشغيل:** #10–#11 و#13–#17 و#19؛ اجتازت مساراتها اختبارات آلية في الجولات السابقة، لكنها لم تحصل جميعها على قبول تشغيلي/بصري نهائي. لا تُغلق جماعيًا بلا أدلة قبول مستقلة.
- **قرار رسمي مطلوب:** [#27](https://github.com/alharbikh/itqan/issues/27) يشمل الاحتساب الرسمي، وتصحيح التقييم المعتمد، والاحتفاظ والملكية والمواعيد وIDP؛ لا تُختلق هذه السياسات في كود الإنتاج دون مصدر واعتماد.
- **قيد خطة خدمة:** [#32](https://github.com/alharbikh/itqan/issues/32) تفعيل حماية كلمات المرور المسرّبة يحتاج خطة Supabase Pro أو أعلى. **لا ترقية مدفوعة دون قرار صريح.**
- **قبول فعلي/بصري مؤجل:** [#20](https://github.com/alharbikh/itqan/issues/20) الكمبيوتر ثم [#21](https://github.com/alharbikh/itqan/issues/21) الجوال. لا تُسجل ناجحة بناء على اختبار API أو SQL.
- **GitHub Projects:** نتائج بحث Issues والمستودع ليست بديلًا عن عناصر لوحة GitHub Projects؛ لم تتوفر أداة قراءة للمشروع نفسه في الموصل الحالي. تُحفظ المطابقة الشاملة بوصفها **غير متحققة**، لا ناجحة ولا فاشلة.

### شروط إغلاق التطوير

1. كل مطلب **معتمد** في #27 تحول إلى تنفيذ واختبارات، أو إلى تأجيل رسمي صريح، دون تعديل سياسة التقييم من التخمين.
2. نجاح `app-and-security` و`schema-bootstrap` على آخر التزام مُدمج، مع استمرار اختبار رفض الوصول العابر للمدارس.
3. لا اختلاف إصدار غير موثّق بين مصدر Worker ونسخة GitHub المنشورة؛ تقارن الأصول العامة بعد كل نشر، وتعمل المراقبة المجدولة.
4. تبقى بنود قبول الكمبيوتر والجوال مفتوحة حتى يرسل المالك نتائج اختباراتها الفعلية ويعتمد الإغلاق.
5. التحقق من مطابقة لوحة GitHub Projects نفسها، أو توثيق عائق صلاحية القراءة بدل الادعاء بأن اللوحة تمت مراجعتها.
