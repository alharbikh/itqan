# إتقان سمارت برو

منصة مدرسية تعتمد **Cloudflare Workers** لتقديم الموقع والواجهات الخلفية وإدارة الجلسات، و**Supabase** للمصادقة وقاعدة PostgreSQL.

## المكونات

- `src/worker.js`: واجهة الخادم، مصادقة Supabase، ملفات تعريف الارتباط الآمنة، التفويض والاستعلامات.
- `public/`: واجهة عربية متجاوبة بخط Cairo، وصفحات الدخول وإنشاء الحساب والمساحات المصرح بها.
- `supabase/migrations/`: تعريفات مخطط PostgreSQL والسياسات المتوافقة مع سجل قاعدة إتقان.
- `tests/`: تحقق تلقائي من المصادقة والصلاحيات والواجهات الخلفية.

المدرسة هي الكيان التنظيمي الأساسي. `schools.education_department` حقل اختياري. الأدوار والصلاحيات تُفرض عبر Supabase Auth وRLS.

## إعداد Cloudflare

1. صِل المستودع بمشروع Cloudflare Workers أو انشر بواسطة Wrangler. لا تُستخدم GitHub Pages لاستضافة التطبيق.
2. اضبط المتغيرين `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` في بيئة Cloudflare Worker.
3. فعّل نطاق التطبيق عبر Cloudflare من لوحة المشروع بعد مراجعة DNS.
4. راجع إعدادات Supabase Auth وعنوان الموقع وروابط الرجوع المسموح بها للنطاق.
5. نفذ `npm test` قبل `npx wrangler deploy`.

لا تُضع `service_role` أو `sb_secret_*` أو كلمات المرور أو بيانات المستخدمين في المشروع أو متغيرات الواجهة.

## الجلسات

تُدار الجلسات من Cloudflare Worker بواسطة ملفات تعريف ارتباط `HttpOnly; Secure; SameSite=Lax`. تصل الواجهة إلى `/api/session` و`/api/schools` دون تلقي رموز Supabase. يُتحقق من الصلاحيات في الخادم ثم بواسطة سياسات RLS في قاعدة البيانات.

إنشاء الحساب لا يمنح عضوية مدرسة أو امتيازات إدارية. تُمنح الأدوار عبر عملية إدارية موثوقة فقط.

## بدء العمل

```sh
npm test
npx wrangler dev
```

تحتوي قاعدة Supabase على سجل الترحيلات المطبق؛ لا تنفّذ إعادة تهيئة مدمرة عليها. أضف ترحيلًا جديدًا لأي تغيير لاحق بعد اختبار حفظ السجلات.

## النشر

يتولى Cloudflare Workers Builds نشر الفرع `main` باستخدام `npx wrangler deploy`، مع تحميل إعدادات `wrangler.jsonc`. تأكد من نجاح نشر Worker الذي يحتوي على `src/worker.js` قبل تفعيل خدمات الحسابات.

يتطلب نشر التطبيق اتصال GitHub مفعلًا لمستودع `alharbikh/itqan`، مع إبقاء فرع الإنتاج `main` واستخدام ملف إعداد Wrangler في جذر المشروع.

## مركز إدارة الموقع

- `/admin.html`: لوحة مدير الموقع بعد تسجيل الدخول بـ Supabase Auth.
- المدارس: إضافة وتعديل وتفعيل وتعطيل وحذف مدرسة **خالية تمامًا من السجلات المرتبطة**. الحذف النهائي لمدرسة تحتوي على عضويات أو ملفات أو تقييمات مرفوض بقاعدة البيانات، واستخدم تعطيل المدرسة بدلًا منه.
- المستخدمون: عرض الحسابات المسجلة وإيقافها أو تفعيلها، باستثناء حساب مدير الموقع.
- عضويات المدارس: إضافة وتعديل عضوية حساب نشط في مدرسة نشطة، مع دور `school_principal` أو `employee`، وإيقاف العضوية.
- الأدوار: عرض مصفوفة الأذونات ومنح/سحب دور `site_admin` لحساب نشط ومؤكد بعملية موثوقة ومُدققة؛ يمنع التعديل الذاتي وسحب صلاحية آخر مدير للموقع.
- سجل التدقيق: معلومات عن عمليات إنشاء/تعديل/حذف المدارس وتغيير الحالة والعضويات والأدوار؛ الحسابات القديمة لا يظهر لها سجل بأثر رجعي.
- أدوات مدير الموقع: روابط Supabase Dashboard وAuth و[هيكل قاعدة البيانات](docs/SCHEMA_CURRENT.md) وملفات الترحيل.
- العمليات الحساسة تمر عبر Cloudflare Worker باستخدام جلسة HttpOnly وJWT المستخدم، ثم دوال PostgreSQL متحققة من الدور في معاملة واحدة؛ لا تُنشر أسرار `service_role`.

**ملاحظة:** لا ينشئ مدير الموقع هوية Supabase Auth باستخدام مفتاح مخوّل عالي الامتياز من المتصفح. يسجل المستخدم حسابه ويؤكد بريده أولًا ثم يُعتمد الوصول إليه إداريًا. تظل أدوات Supabase SQL Editor متاحة لمالك مشروع Supabase نفسه، ولا يمكن للوحة الموقع تنفيذ SQL اعتباطي.

## مساحة المدرسة

تفتح الواجهة `/school.html` بعد اعتماد عضوية المستخدم في مدرسة نشطة. تعرض قائمة جانبية يمينية بثلاث حالات: كاملة، أيقونات فقط، ومخفية، مع اختيار المدرسة من العضويات التي تتحقق منها Supabase RLS.

- الموظف يرى المدارس المسموحة له، وصلاحية وصوله وعمله الحالي، وأقسام الخدمات القادمة دون عمليات كتابة أو بيانات تجريبية.
- مدير المدرسة يستطيع، بالإضافة إلى ذلك، الاطلاع على منسوبي **مدرسته فقط** عبر `GET /api/school/members?school_id=<UUID>`؛ ويرفض الخادم الحسابات غير المخولة والموظفين ومديري المدارس الأخرى، وتفرض RLS الترشيح الفعلي للصفوف.
- بيانات الجلسة لا تُحفظ في `localStorage` أو `sessionStorage`، ويستمر الاعتماد على ملفات تعريف ارتباط `HttpOnly` والاتصال بالخادم.
- قسم خدمات المدرسة يوجه المستخدم إلى الواجهات التشغيلية الحالية `/performance.html` للأداء والشواهد، و`/link.html` للارتباط، وإدارة المنسوبين لمدير المدرسة. تُفرض صلاحيات الكتابة على الخادم وRLS، ولا يُعرض التقييم الذاتي غير المنفذ كخدمة جاهزة.


## منظومة دورة الأداء — المهام #12–#16

- `/link.html`: الموظف يطلب ربط ملفه الوظيفي المعتمد بمدرسته، ويمكنه فك الارتباط مع حفظ التاريخ؛ ويُراجع مدير المدرسة الطلبات ويعتمد الهوية.
- `/performance.html`: مساحة العمل المدرسية للمعايير، والإقرار بالاطلاع، ومكتبة الشواهد الشخصية والربط الاختياري بالمعايير، والمراجعة النصفية الوصفية، وإجراءات التقييم المساند.
- `/frameworks.html`: مساحة مدير الموقع لاستيراد JSON ومراجعته، وحفظ المسودات، والاعتماد والنشر كإجرائين منفصلين، وتحديد السنة الدراسية وحدود مواعيد دورة الأداء.
- تحتفظ قاعدة PostgreSQL بإطار المعايير وإصداره والأوزان والتقديرات الموزونة، وتمنع عضويتين نشطتين لنفس الحساب. لا يعتمد المتصفح وحده في التفويض؛ تتحقق PostgreSQL وRLS من كل عملية.
- عند انتهاء الارتباط: تجميد التقييم غير المكتمل، وإلغاء التفويضات والشواهد الشخصية المشتركة مع المدرسة السابقة. استكمال التقييم يكون بطلب موثق وموافقة مخولة مستقلة ومدة صلاحية محددة.
- **حدود النطاق الحالي:** أصبحت المرفقات الفعلية مرتبطة بــSupabase Storage الخاص، وتبقى اختبارات المتصفح الفعلية مطلوبة، وتظل حسابات الإشراف الخارجي مؤجلة. يجب اختبار التدفقات بحساب مدير مدرسة وموظف حقيقيين قبل إغلاق مهام التشغيل. لا يمثل تقييم إتقان اعتمادًا رسميًا بديلًا عن فارس.
- اختبارات GitHub Actions تعيد بناء مخطط Supabase معزولًا وتختبر سيناريوهات الربط والمعايير ودورة الأداء عبر معاملات لا تحفظ بيانات الاختبار. ترحيلات المستودع مطابقة لسجل الترحيلات المطبق في Supabase.


## رفع مرفقات الشواهد — المهمة #17

- من صفحة `/performance.html` يختار الموظف شاهدًا ثم ملفًا لرفعه في حاوية Supabase الخاصة `itqan-personal-evidence`.
- يدعم PDF وPNG وJPG وWebP وDOCX وXLSX، بحد **5 ميجابايت لكل ملف** و50 ملفًا لكل شاهد عبر الواجهة الخلفية. لا يدعم الصيغ التنفيذية أو ZIP العامة.
- لا تصل رموز Supabase إلى JavaScript في المتصفح؛ يمر رفع الملف وتنزيله وحذفه عبر Cloudflare Worker مع جلسة محمية وفحص ملكية الشاهد.
- لكل شاهد مرفقات مستقلة عن ربطه بمعيار، ولا تظهر المرفقات للمدرسة إلا إذا شارك الموظف الشاهد معها. إلغاء المشاركة ينهي الإتاحة للمدرسة، دون فقدان ملفات الموظف الشخصية.
- يبقى الوصول الشخصي للمرفقات بعد فك ارتباط الموظف بالمدرسة. التنزيل من مسار محمي يُقدم بصيغة Attachment لمنع العرض التنفيذي داخل الموقع.
- فحوص CI تغطي API وقواعد RLS في Supabase المعزولة؛ الاختبار التشغيلي والبصري مؤجل وفق اعتماد المالك، لذلك تبقى المهمة #17 مفتوحة إلى حين هذا الاختبار.
